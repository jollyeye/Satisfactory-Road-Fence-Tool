# Road Maker 1.3.0 roadmap

1.2.1 is released (2026-11-12). Work for the next version; the 1.2.0 roadmap (`ROADMAP-1.2.0.md`) is kept as history.
Status words: **DONE** (tested in game), **built, awaiting test**, otherwise to do.

## Done
- **Map road layer**: DONE in code (2026-11-12, `Private/Map/RMMapLayer.cpp`). Our canvas sits in the map's `Overlay_0` right after `BPW_MapAreaPainter` (the game pans / zooms it; icons stay on top). 512 m tiles at 1 px/m, painted at 2x and averaged (anti-aliasing), with mips and colour bleed at the edges; only tiles with roads exist. Roads are painted in 4 m pieces and intersections whole, all in height order, so overpasses and ramps cover what they pass over. Fill by look (cyberpunk = primary colour), side lines 1.5 m just inside the edge, only when on, in the secondary colour. Only while the map is open: changed pieces repaint their tiles; work spread over frames (3 ms building, 4 ms painting). Still to test: big save first open. Later: "Roads" map filter toggle (the game's filters currently don't work, check once they do).
  - Bridge shadows: tried and dropped (2026-11-12): not worth the edge cases (joined roads, parallel roads); height order is enough. If ever wanted, the agreed definition: the centre lines cross (seen from above), 4 m+ clearance measured at the crossing point, intersections count by area and never cast, the 3 m band on both sides darkens only the crossed piece.
- **Intersection curbs like the vehicle paths** (2026-11-12): the roads' Bezier algorithm (MakeQuadratic) tried and rejected (odd S-curves, paths left the curb). Now trying curbs made with the same curve as the vehicle paths / rails through the junction (`MakeFixedEnds`, circular-arc tangents): in the 8 test layouts of `Tools/IconSource/intersection_curb_bezier.py` no lane path leaves the curb (the old curbs had 1 in a narrow Y). Simple curbs stay as fallback when the outline would cross itself. Every intersection changes a little on load (curbs slightly rounder): fences on curbs may need rebuilding. Keep only if it looks better in game. **DONE: kept (2026-11-12).** Also: side-by-side road ends (split roads, or roads that line up) count as one road slot per 4 foundations of width, one outline and one arrow in the pick overlay.

Next: **Join Fence** (own tool, less strict on length, same curve rule); joining fences together with roads not planned for now. The road itself (hologram, reveal animation, sounds) is complete.

## Later (1.4.0 or after)
- **Integration with other mods / Automated Machines** (discussed 2026-11-12, postponed): no hard link between mods; a
  name-based contract through Unreal reflection (works in the shipped game, where metadata is stripped). An actor is
  "automatable" when it has `AM_GetAlarms()`, `AM_GetActions()`, `AM_DoAction(Action, On)` and an `AM_OnAlarm(Alarm)`
  event; Automated Machines finds them by name and lists them like a machine's alarms / actions. Road Maker candidates:
  intersection "Vehicle enters / leaves", "Busy / Clear" (the detection traffic lights need), road "Vehicle on road /
  Road clear", boom barrier actions "Open / Closed" + alarms, traffic light "Turns green / red" + "Hold red". Optional
  extra: a Road Maker subsystem publishing world events (road built / dismantled / cut / split / merged / joined,
  intersection built) for other mods. Open questions: `AM_` naming as the shared standard; which vehicles count.
